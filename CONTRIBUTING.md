# Разработка и выпуск релизов

[← README](README.md)

## Локальная установка

Для разработки можно клонировать репозиторий:

```sh
git clone https://github.com/eQurane/ytm-enhancer.git
```

Загрузите папку клонированного проекта с `manifest.json` как распакованное расширение по [инструкции установки](README.md#установка). Сборка и установка npm-пакетов не требуются. После изменения файлов нажмите **Обновить** на карточке расширения и перезагрузите вкладку YouTube Music.

Архив из релиза содержит только `manifest.json` и `src/`, без тестов и файлов разработки. Для проверок и визуального стенда используйте клонированный репозиторий.

## Проверка и разработка

Для проверок нужен Node.js 20+:

```sh
npm run check
```

Зависимостей нет, `npm install` не требуется. GitHub Actions запускает эту же команду на Node.js 22 и 24 при push и pull request в `main`.

Проверяются синтаксис, Manifest V3, версии, локальные ресурсы, точный домен внедрения, команды и страницы плейлистов, кэш и ограничение запросов, обработка ошибок и гонки настроек. Для громкости проверяются перехват колеса, ввод, границы, синхронизация, mute, замена компонентов и восстановление при отключении. Тесты используют фикстуры, не меняют ваш аккаунт и не делают сетевых запросов.

Для визуального стенда со смоделированными компонентами сайта:

```sh
node scripts/preview.mjs
```

Откройте `http://127.0.0.1:4173/tests/fixtures/queue.html`. Стенд позволяет выбрать плейлист и модификатор, проверить историческое наличие песен, скрытие кнопок, дубли, замену строки, ошибки и отключение без установки расширения. Внизу доступны оба регулятора громкости, mute, штатное изменение уровня и замена регуляторов. Счётчик изменений помогает проверить отсутствие двойного шага колеса. Стенд не заменяет проверку интеграции с настоящим YouTube Music.

После установки проверьте в YouTube Music:

- Лайк → снять лайк → дизлайк → снять дизлайк для текущей и другой песни.
- Согласованность оценок в очереди, повторяющихся строках и нижнем плеере.
- Первое добавление открывает выбор для нажатой песни; после выбора плейлиста обычный клик добавляет или удаляет песню. Повторяющиеся строки показывают одинаковые галочки, воспроизведение не переключается.
- Выбор другого плейлиста по Shift/Ctrl/Alt + клик не меняет плейлист по умолчанию без отметки «Сделать по умолчанию» и не создаёт дубли.
- Всплывающее окно у иконки расширения загружает список на вкладке музыки; настройка сохраняется после перезагрузки, удалённый плейлист не заменяется автоматически.
- Прокрутку, смену очереди, переходы без перезагрузки, длинные названия и узкую панель.
- Навигацию Tab, активацию Enter/Space и включение/отключение через настройки расширения.
- При ошибке сети не остаётся ложной успешной оценки, доступна повторная попытка.

Ошибки расширения доступны на его карточке, сообщения адаптера — в консоли вкладки YouTube Music.

## Версии и релизы

Версии, Git-теги и имена архивов используют **`yy.mm.dd.hhmm`**, время — **Asia/Seoul (UTC+9)**. Команда выставляет текущее время сразу в `package.json` и `manifest.json`:

```sh
npm run version:date
npm run check
```

В интерфейсе расширения отображается `version_name` с этим номером. Техническое поле `version` содержит те же четыре числа без ведущих нулей: например, `27.01.02.0005` → `27.1.2.5`. Это [требование Chromium](https://developer.chrome.com/docs/extensions/reference/manifest/version). `package.json` приватный и не предназначен для публикации в npm.

Зафиксируйте изменения в Git, создайте тег с точным значением `version_name` и отправьте коммит и тег. Например, для версии `26.10.19.1415`:

```sh
git tag 26.10.19.1415
git push origin main
git push origin 26.10.19.1415
```

GitHub Actions повторно проверит проект, упакует файлы из этого коммита и создаст Release с ZIP. При несовпадении тега и версии публикация остановится. Для каждого нового релиза нужен новый номер; несколько релизов в одну минуту не поддерживаются.

Для получения такого же архива локально после коммита:

```sh
npm run package
```

Результат — `dist/ytm-enhancer-<версия>.zip`. В корне архива находятся `manifest.json` и `src/`. Локальные изменения файлов расширения перед упаковкой нужно сохранить коммитом; архив берётся из `HEAD`.

См. также [управление и настройки](docs/usage.md) и [устройство и ограничения](docs/technical.md).
